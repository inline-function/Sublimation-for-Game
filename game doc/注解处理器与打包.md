# SfG 注解处理器与打包

SfG 的编译期纪律与产物组装都由脚本处理器 `annotation processer/game.subs` 完成，
**不需要改编译器**——它运行在主仓的注解处理器框架（`.subs` 脚本 + `@postcompile` 钩子）上。

## 处理器职责

`game.subs` 的处理器名（文件名）= `game` = 它关注的注解。

1. **白名单校验**：所有 `@game` 函数必须在 45 个已知名字里（`isGameBuiltin`）。
   未知名 → 编译期报错。目的：**把笔误挡在编译期**——少写/错写桥接名不再等运行期才崩。
2. **`@host` 校验**：`@game` 声明必须同时带 `@host`（无体桥接的语言机制）。
3. **`@impure` 校验**：桥接有副作用，缺 `@impure` 给警告。
4. **无体校验**：`@game` 声明不能有函数体（体由壳工程提供）。
5. **编译后打包**（`// @postcompile build`）：见下。

## 编译后阶段：打包成可开网页

`build()` 期望编译参数（`-A key=value`）：

| 键 | 说明 |
| --- | --- |
| `gameApp` | 壳工程目录（含 `build/package-game.ps1`） |
| `gameJs` | 编译器 JS 产物路径（`-o` 的同一文件） |
| `gameOut` | 输出目录（默认 `gameApp\\build\\game`） |

> 键名刻意避开安卓处理器的 `appDir`/`jsPath`/`outDir`/`sdkDir` 命名空间。
> 从 SfG 仓根运行时两者不会同时触发；即便从主仓根运行（默认处理器含 android.subs），
> 各自的 `-A` 键互不干扰，可共存。

打包步骤（`game-app/build/package-game.ps1`）：

1. 建立 `gameOut/` 及子目录 `js/`、`vendor/`、`assets/`；
2. 复制壳工程的 `index.html`、`js/game-runtime.js`、`vendor/kaplay.js`；
3. 复制 JS 产物为 `app.js`、复制 `app/assets/*`；
4. PowerShell 成功写 `ok|<gameOut>` 退 0，失败非 0——处理器按退出码与输出报
   `E-PROCESSOR-SCRIPT`（编译后阶段的诊断只报告不阻断，JS 产物始终已生成）。

## 端到端命令

```bat
cd F:\SublimationProject\sublimation for game
F:\KotlinProject\Sublimation\cli\build\install\cli\bin\cli.bat compile app ^
    -o game-app\build\app.js ^
    -A gameApp=game-app -A gameJs=game-app\build\app.js
```

- **CWD 必须是 SfG 仓根**：处理器按 CWD 相对路径装载（默认目录 `annotation processer/`、
  脚本 stdlib `core/`）。首次使用或主仓更新后先同步：
  `powershell -ExecutionPolicy Bypass -File scripts\sync-deps.ps1`。
- 产物：`game-app/build/game/`（`index.html` + `app.js` + `js/` + `vendor/` + `assets/`），
  里面 `index.html` 直接用浏览器或静态服务器打开即可玩。
- 验证：`node test/smoke-test.js`（用 KAPLAY 桩跑演示的交互逻辑，23 项断言）。

## 提示

- 编译后阶段的 `processorInfo`（SUPPLEMENT 级）默认不打印，加 `-v` 可见
  （`game-app/build/game` 的实际产出状态以文件为准）。
- `game.subs` 用 List 模式遍历 `funNames`，依赖 CWD 可见的 `core/`——这是
  「从仓根运行」要求的另一半原因。
