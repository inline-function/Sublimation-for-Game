# SfG 游戏标准库

SfG（Sublimation for Game）给 Sublimation 提供「写网页游戏」的标准库：所有游戏能力都是
`@game` 标注的**无体桥接函数**——声明在 `.subl` 里、函数体由壳工程的
`game-app/js/game-runtime.js` 用 KAPLAY 实现。**宿主桥 ABI（t38 定案；t43 全链路统一）**：宿主提供 `globalThis.__subl.call(op, args)` 单入口分派（`__SG_OPS` 注册表，op 名 = 声明的函数名；`__subl.ops()` 枚举 45 op；未知 op 抛明确错误）；编译器（t43）对用户 `@host` 无体声明也统一生成单入口调用，运行时闭包封装、零桥全局污染（t40 过渡期的裸名实现已回撤）。
Sublimation 侧不需要知道 KAPLAY，只看到这 48 个声明。

## 桥接模型

```subl
@game @host @impure fun onKeyDown(key: Str, body: (Any) => Null): Null
```

- `@game`：游戏内建标记。注解处理器 `game.subs` 据此做白名单与态度校验（见
  [注解处理器与打包](注解处理器与打包.md)）。
- `@host` + 无体：编译器不生成函数定义，调用点翻成宿主桥单入口
  （`onKeyDown("left", ...)` → JS `globalThis.__subl.call("onKeyDown", ["left", ...])`）。
- `@impure`：桥接有副作用，符合语言的纯净性纪律（缺失会被处理器警告）。
- 运行期由壳工程的 `game-runtime.js` 提供 `globalThis.__subl.call` 分派：宿主侧 `__SG_OPS` 注册表（单一真源，op 名与这里的声明一一对应，与 game.subs 处理器的 op 白名单对齐）转发到 KAPLAY 上下文 API；未知 op 抛明确错误。

## 类型约定

| Sublimation 类型 | 含义 |
| --- | --- |
| `Rat` | 所有的坐标、尺寸、时间间隔、速度（JS number） |
| `Nat` | 视口宽高等非负量 |
| `Str` | 键名、标签、十六进制颜色、文本 |
| `Any` | 游戏对象（game object）、组件、Vec2——KAPLAY 对象对 Sublimation 不透明 |
| `List[Any]` | `objsByTag` 的返回（编译器内建 List，无需挂载 core） |

- **没有运算符优先级**：`a + b * c` 是左结合，乘法必须显式括号：`a + (b * c)`。
- **块体返回值**：lambda 体里写尾表达式不会自动返回，要 `return`。
- 编译器内建的 `rand()`、`toStr()`、`concat()` 不用挂载 core 即可用（`@root` 特化）；
  挂载 `core/` 后还有完整的字符串/数学/集合标准库。

## API 总表（55 个：t65 新增 onMouseRelease/onMouseMove，t68 新增矢量地图 5 个）

### 启动与场景（`game.subl`）

| 函数 | 签名 | 说明 |
| --- | --- | --- |
| `gameStart` | `(width: Nat, height: Nat): Null` | 初始化 KAPLAY 画布（`global: false`，固定逻辑画布——默认拉伸铺满窗口，线性插值放大可能模糊），游戏入口必须最先调用 |
| `gameStartFit` | `(width: Nat, height: Nat, letterbox: Bool, crisp: Bool): Null` | 初始化 KAPLAY 画布并**自适配窗口**：`stretch` 恒开（画布跟随窗口尺寸），`letterbox=true` 保持宽高比（留黑边不变形），`crisp=true` 关平滑插值（`image-rendering: pixelated`，像素风锐利）。逻辑坐标体系不变——仍按 `width×height` 写坐标，缩放由 KAPLAY 外层完成 |
| `gameGravity` | `(g: Rat): Null` | 设置重力加速度（像素/秒²） |
| `sceneAdd` | `(name: Str, body: (Any) => Null): Null` | 注册场景及其初始化函数 |
| `sceneGo` | `(name: Str): Null` | 切换/重启场景（重开等） |
| `viewWidth` | `(): Nat` | 视口宽（逻辑画布尺寸，stretch 下不随窗口变） |
| `viewHeight` | `(): Nat` | 视口高（逻辑画布尺寸） |
| `winWidth` | `(): Nat` | 真实窗口宽（CSS 像素；无窗口环境回落为画布逻辑尺寸） |
| `winHeight` | `(): Nat` | 真实窗口高（CSS 像素；无窗口环境回落为画布逻辑尺寸） |

## 矢量地图数据（geo.subl，t68 新增）：凹多边形渲染与命中

省级行政区划这类形状有两个硬约束：**轮廓是任意凹多边形**（甘肃狭长带、黑龙江半岛形），
**一省是多环**（山东含半岛 + 岛屿、含多个飞地片段）；rect 拼接既难看又会误触，area() 的 rect
命中对狭长省会直接失效。geo.subl 给一组矢数据 op：

| op | 语义 |
| --- | --- |
| mapLoad(t: Str): Any | 载入紧凑文本省份表并烘焙渲染结构，返回地图句柄 |
| mapProvCount(m: Any): Nat | 省份数量 |
| mapProvName(m: Any, i: Nat): Str | 按下标取省名 |
| mapProvObj(m: Any, i: Nat, hex: Str): Any | 创建该省精灵对象（位置=烘焙 bbox 左上角） |
| mapHitProv(m: Any, x: Rat, y: Rat): Int | 射线法点在多边形内；命中返回省下标，否则 -1 |

**数据格式**（紧凑文本表，省掉 JSON 解析与字符串转义）：每省一段
`省名:环;环;...`，省段以 `|` 分隔；环是逗号分隔的 `x y` 顶点表（世界坐标像素）。
数据由预处理脚本从行政区划 GeoJSON 生成（投影到逻辑画布坐标，直角等距，四舍五入 1 位小数），
以 `@impure fun mapGeoJson(): Str` 这样的源码字面量进 SfG，编译期即内联。

**烘焙渲染**（桥实现）：mapLoad 每省一次性画进一张小 canvas——白底 fill、1.2px 黑边
stroke——再 loadSprite(画布)。canvas2d 填充对凹多边形与多环天然正确、边缘抗锯齿。
渲染期每省只是一个 sprite 对象，**换高亮色 = objUse(o, compColorHex(色))**：
KAPLAY 的 use() 按组件 id 替换，tint 乘色让白底取填色、黑边在任何 tint 下保持黑——
高亮零几何计算、换色不重建精灵。

**命中判定**：mapHitProv 对每省各环做经典射线法（((y1 > y) !== (y2 > y)) && x < ...
交叉计数）；省级行政区互不重叠（DataV 数据已按行政边界切开飞地），首个命中即返回，
无需环序处理。点在多边形内对任意凹形精确，狭长省（甘肃/内蒙古）与小直辖市
（北京/天津/上海）都能正确点选——这是本 op 取代 area() rect 命中的原因。

**模板**（见 GameDemo 中国地图 demo）：

```subl
@impure
fun renderProvsLoop(geo: Any, n: Nat, i: Nat, sel: Int): Null =
    if (i >= n) null
    else {
        var hex: Str = if (i == sel) FILL_SEL() else FILL_NORMAL()
        var o: Any = mapProvObj(geo, i, hex)
        objTag(o, "prov")
        renderProvsLoop(geo, n, i + 1, sel)
    }
```

点击（onMouseDown 记起点、onMouseRelease 判定，无位移才算点）：

```subl
var hit: Int = mapHitProv(geo, pressX, pressY)
if (hit >= 0 && hit != sel) {
    sel = hit
    objsDestroyTag("prov")   // 全量重建（资产已烘焙，成本极低）
    renderProvs(geo, n, sel)
    objTextSet(label, selLabel(mapProvName(geo, hit)))
}
```

**注意**：换高亮时重建全部省份对象（objsDestroyTag + 重建）比按列表换色更省键入、
也避开了 SfG 列表按索引取句柄的样板；烘焙精灵在 mapLoad 时已入资产缓存，重建不重画 canvas。
## 写游戏的套路

```subl
@impure
fun main(): Null {
    gameStart(640, 480)                      // 1. 启动
    spriteLoad("bean", "assets/bean.png")    // 2. 资源
    @mut var score: Int = 0                  // @mut 才能被 lambda 改写
    val player: Any = spriteAdd("bean", 300.0, 400.0)
    objAddArea(player)                       // 3. 要碰撞就挂 area
    onKeyDown("left") { _e => objMove(player, -6.0, 0.0) }
    every(1.0) { _e => { score = score + 1 } }
    onUpdate { _dt => ... }                  // 4. 每帧逻辑
    objOnCollide(player, "enemy") { _o => ... }   // 5. 碰撞
    null
}
```

完整示例见 `app/main.subl`（豆豆躲方块：移动、刷怪、计分、碰撞结束、空格重开）。
