# SfG 壳工程与运行

壳工程 `game-app/` 提供 Sublimation 游戏在浏览器里跑起来所需的一切：
KAPLAY 引擎、桥接运行时、页面容器与打包脚本。

## 目录结构

```
game-app/
  index.html                 页面：依次载入 vendor/kaplay.js、js/game-runtime.js、
                           app.js，然后调用 __subl.main()（S-1 装载模型）
  js/
    game-runtime.js          桥接层：实现 48 个 @game 声明的 op（__SG_OPS 注册表），经
                          globalThis.__subl.call(op, args) 单入口分派 → KAPLAY 上下文
  vendor/
    kaplay.js                KAPLAY v3001.0.19（MIT，见下）
    README.md                供应商说明与升级方法
  assets/                    精灵资源（app/assets/ 的打包目的地示例）
  build/
    package-game.ps1         打包脚本（处理器调用）
    app.js                   编译器产物（-o 目标）
    game/                    ——打包产物（可发布）
```

## 运行

打包产物 `game-app/build/game/` 是一个**自包含网页**：

```bat
cd "F:\SublimationProject\sublimation for game\game-app\build\game"
python -m http.server 8080
```

然后浏览器开 `http://localhost:8080/`。（用静态服务器即可；`file://` 下 fetch/模块限制
依浏览器而异，建议总是走 http。）

**演示（俄罗斯方块）**：← → 移动（按住自动重复）、↑ 旋转、↓ 软降、空格硬降、
P 暂停；行消除计分（单 100 / 双 300 / 三 500 / 四 800）、每 10 行提速、
右侧 next 预览与 score/lines/level；Game Over 后空格重开。

**装载模型（S-1，--target=browser）**：app.js 不自执行 `main`，而是导出
`(globalThis.__subl || (globalThis.__subl = {})).main`；index.html 在三个脚本载入后
调用 `globalThis.__subl.main()`（main 为 async；失败则在页面尾部报错）。留宿主介入点，
正是 S-1 路线的意义（装载与执行分离，宿主可先注入桥/做门控）。

## 桥接实现（`js/game-runtime.js`）

- 判 `typeof kaplay === "function" ? kaplay : kaplay.default`，兼容 UMD 与 esm 载入。
- `gameStart` 以 `{ width, height, global: false, background: "#101820" }` 初始化，取回 KAPLAY 上下文存内部；两入口均传 `background`——未设时 KAPLAY 用 2×2 黑白棋盘格纹理（`bgTex`，wrap=repeat）平铺画布，画面任何未绘制区域（地图视口边角、海面 rect 之外）都会露出黑白格子；统一深色清屏后未绘制区域一律深色（#101820 与地图海面 rect 同色，观感无缝）。
  其他桥接函数都有「未初始化」守卫（`__sgK()` 抛明确错误而非隐式 undefined）。
- `objMove(o, dx, dy)` 是**直接位置增量**（不是 KAPLAY 的按秒速度 `move()`），
  与「像素/帧」的 Sublimation 侧直觉一致；要按秒移动就在 `onUpdate` 里乘 `dt`。
- `compColorHex` 支持 `#rgb`/`#rrggbb` 与 10 个命名色。
- `onUpdate` 回调收到的参数是 `k.dt()`（秒）。
